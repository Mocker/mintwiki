# MintWiki — Cloudflare runtime

The Cloudflare deployment of MintWiki: a **Worker** front door, one
**Durable Object** (SQLite storage) holding the wiki's manifest, and
**R2** for revision objects, page mirrors, and the rendered site.

The Go binary at the repo root is the **reference implementation**.
This package implements the same contract — same routes, token lane,
receipt chain, and tool definitions (the canonical
[`tools.definitions.json`](../tools.definitions.json), generated from
the Go definitions and drift-checked in CI). The black-box
[`conformance/`](../conformance) suite must pass against both
runtimes; where rendered HTML details differ (goldmark vs marked),
conformance compares content and revision footers, never bytes. The
design is specified in the Milestone 3 scope (in the project record)
and the mapping is:

| Go runtime              | Cloudflare runtime                        |
| ----------------------- | ----------------------------------------- |
| SQLite file             | Durable Object SQLite (`ctx.storage.sql`) |
| `revisions/ab/<id>.md`  | R2, same key layout                       |
| `data/pages/<path>.md`  | R2 `pages/<path>.md`                      |
| `data/site/`            | R2 `site/`, served by the Worker          |
| receipts log file       | `receipts` table in the Durable Object    |
| signing key file        | `SIGNING_SECRET` Worker secret            |
| owner CLI               | admin API (`OWNER_ADMIN_TOKEN`), M3.4     |

## Owner operations: the admin surface

Every owner operation the Go runtime performs through its CLI is
an endpoint under `/v1/admin/*`, gated by the `OWNER_ADMIN_TOKEN`
Worker secret (a credential distinct from the signing secret and
from every service credential; unset, the surface answers 503).
Use the bundled client — same verbs as the Go CLI:

```sh
export MINTWIKI_URL=https://mintwiki.example
export MINTWIKI_ADMIN_TOKEN=…   # the secret's value; env only, never a file
node scripts/admin.mjs service add --name anna --ceiling "/notes/**" --tiers allow,approve --max-ttl 1800
node scripts/admin.mjs mint-requests --status pending
node scripts/admin.mjs seed            # idempotent demo seed
node scripts/admin.mjs verify-receipts
```

Endpoints: `POST /mint`, `POST /revoke`, `POST /services`
(credential generated server-side, returned exactly once — only
its hash is stored), `GET /services`, `POST /services/revoke`,
`GET /mint-requests`, `POST /mint-requests/decide`,
`GET /proposals`, `POST /proposals/accept`, `GET /receipts/verify`,
`POST /seed-page`. Decisions and accepts are receipted through the
lane, as the Go CLI receipts them; listings never carry credential
material.

This surface replaced the M3.1–M3.3 bootstrap routes
(`/internal/seed-page` and friends behind an `ALLOW_SEED` var).
Those are removed, and `/internal/*` is now Worker↔Durable-Object
plumbing that is never forwarded from outside.

The lane needs `SIGNING_SECRET` (Worker secret; hex, the same format
as the Go runtime's `signing.key` file). Unset, the lane fails
closed.

Owner operations live on the admin surface (next section).

## Develop

```sh
npm install
npm run dev          # wrangler dev on http://localhost:8787
npm run seed         # import ../../deploy/seed via the admin client
npm test             # vitest against the Workers pool (miniflare)
npm run typecheck
```

Seeding (and every other owner operation) needs the admin token:
for local dev, put `OWNER_ADMIN_TOKEN` in `.dev.vars` (gitignored)
and export the same value as `MINTWIKI_ADMIN_TOKEN` for the client.

## Deploy (M3.5, Ryan's steps included)

```sh
npx wrangler r2 bucket create mintwiki-blobs
npx wrangler secret put SIGNING_SECRET       # Ryan only — never in code
npx wrangler secret put OWNER_ADMIN_TOKEN    # Ryan only
npx wrangler deploy
```

The `mintwiki.gup.io` custom domain is attached in the Cloudflare
dashboard.
